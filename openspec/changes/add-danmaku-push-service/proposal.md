# Proposal

## Why

需要一个面向 Web 端的通用推送服务，首个落地场景是**中小主播直播间的弹幕**。弹幕负载的特征（高扇出、极短消息寿命、可合并、单向广播）与通用 IM 差异极大，若一开始按"通用内核 + 场景适配"设计，会在唯一确定的弹幕场景上付出不必要的抽象成本。

本变更在没有确定业务场景的窗口期**主动收窄定位为弹幕优先**，先把这个唯一确定的场景做到位，再在真实客户出现后扩展。

## What Changes

- 新建一个 Go 编写的多租户推送服务，包含数据面（无状态 WebSocket 网关）与控制面（持久化配置）两大部分。
- **数据面无状态**：网关之间不共享订阅状态，发布消息经消息总线广播后由各网关本地过滤，不做频道分片、不做连接迁移。
- **QoS0 语义**：不持久化消息，不补发、不重放，允许丢失、重复与乱序。
- **容量目标**（三者互相自洽，构成一个确定的设计点）：

  | 指标 | 值 |
  |---|---|
  | 单机连接数 | 100,000 |
  | 每观众带宽预算 | 2 KB/s（约 10 条 200B 弹幕/秒） |
  | 单机出口 | 1.6 Gbps（网卡 3.2 Gbps 的 50%） |
  | 平台入站总量 | 1,000 QPS（所有房间总和） |
  | 端到端延迟 | P50 < 50ms，P95 < 100ms，P99 < 200ms |
  | 连接建立时间 | < 1s |

  对应负载模型：100 个并发千人房，每房发布 10 QPS。

- **合包默认开启**：同一频道的多条消息在固定窗口内合并为一个包推送。它是**延迟旋钮而非带宽旋钮**——合包不降低总字节数。
- **频道级限额由每观众预算推导**：`p_max = min( 每观众带宽预算 / 名义消息大小 , 每观众目标收包率 x 合包率 )`。两个边界都与订阅者数量无关——每个订阅者都会收到每一条发布，所以观众体验只取决于发布速率。大频道只是按比例消耗更多总资源，而不会获得更高的发布速率。
- 具备过载降级阶梯（L0 正常 → L3 仅保留高优先级消息），使单机吞吐在不迁移连接的前提下获得约一个数量级的提升。
- 提供 JavaScript/TypeScript Web SDK，含自动重连（指数退避 + 随机抖动）、重连后批量重订阅、TLS 会话复用与丢弃提示。

### 明确不做（MVP 排除项）

以下能力在原始需求清单中出现，但经容量与场景推演后判定为 MVP 之后的工作：

- 消息持久化、历史消息、离线消息与离线补发、消息重放
- 强 ACK（QoS1/QoS2）、全局顺序、恰好一次语义、事务消息
- 频道分片与房间级调度（千人房扇出可单机解决；万人房以上才需要）
- **按标签过滤的订阅**——它与「一次序列化、共享字节扇出」的高性能路径互斥，冲突时优先保性能
- 消息采样与丢弃合并（超载时用降级阶梯，不在正常路径引入有损行为）
- 频道注册表与显式 CRUD（频道本质是 key，即用即建）
- IP/Referer 白名单、设备维度封禁、批量发布
- App / 小程序 SDK、多区域与边缘节点、计费系统、复杂 AI 审核
- 多端同步、已读回执、正在输入、私聊/群聊/好友关系

## Capabilities

### New Capabilities

- `access-control`: 多租户与应用接入、AppKey/Secret/Token 认证、发布与订阅权限分离、租户配额与限流、传输安全（WSS/TLS）、CORS 策略、防重放。
- `channel-subscription`: 频道寻址模型、订阅与退订、单连接多频道、握手期批量订阅、频道级限额。
- `message-publishing`: 发布接口、消息信封与校验（ID/时间戳/TTL/大小上限）、发布准入（限流、去重）、失败策略（丢弃/降级/快速失败）。
- `fanout-delivery`: WebSocket 传输与鉴权握手、扇出语义、合包推送、慢消费者处理与背压、丢弃缺口通知、心跳与重连、连接排空。
- `content-moderation`: 敏感词匹配与拦截/替换/打标、用户禁言与封禁、IP 封禁、重复与广告内容拦截、弹幕频率限制、审计日志生成。
- `admin-console`: 管理接口——租户/应用、频道、在线连接、敏感词、封禁、配额与限流、功能开关与降级开关。
- `observability`: 指标（连接数、发布量、推送量、扇出倍数、延迟、丢弃率、慢消费者数、带宽）、告警、审计日志查询、容量报表。
- `web-sdk`: JS/TS SDK 的连接与鉴权、订阅管理、心跳与自动重连、消息回调、错误与背压/丢弃提示、多频道管理、弱网与代理环境处理。
- `deployment`: 容器化交付、无状态水平扩展契约、健康检查、配置分发、灰度与功能开关、压测工具与容量报表产出。

### Modified Capabilities

无（项目当前没有任何既有 spec）。

## Impact

- **全新代码库**：当前仓库除 `openspec/` 外没有任何源代码，本变更从零开始搭建。
- **新增运行时依赖**：Go 工具链；WebSocket 库；Aho-Corasick 敏感词匹配实现；消息总线客户端；PostgreSQL/MySQL 驱动；指标采集与导出组件。
- **新增外部依赖**：消息总线（Redis Pub/Sub 或 NATS Core）、关系型数据库（租户/配置/审计）、云厂商负载均衡与公网带宽。
- **新增部署形态**：容器化网关（水平扩展）+ 控制面服务（可缩容）。
- **对外接口**：HTTP 发布接口、WebSocket 订阅协议、管理 REST 接口、三套凭据体系（AppKey/Secret 用于管理，Token 用于客户端）。
- **无破坏性变更**：本变更为项目首个能力，不影响任何既有接口。
